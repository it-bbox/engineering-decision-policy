# Установка и использование

## Посмотреть и запустить

Скачай ZIP, распакуй его и открой `index.html`. Один HTML содержит стили,
симулятор и доступные для просмотра исходники; сеть не требуется. Ссылка на
репозиторий и загрузка полного ZIP используются только по явному нажатию.
Для runnable demo в папке комплекта выполни:

```sh
python3 scripts/run_demo.py
python3 -m unittest discover -s tests -v
```

Результаты создаются в `demo/reports/`. Скрипт не устанавливает пакеты,
не обращается к сети и не меняет настройки агента.

## Codex

Скопируй папку комплекта целиком в
`<project>/.agents/skills/engineering-decision-policy/`. Внутри должны остаться
SKILL.md, docs, scripts и configs: относительные ссылки зависят от этого.
Затем скопируй выбранный `configs/*.json` в
`<project>/.engineering-policy/policy.json` и адаптируй scope, suite_id, проверки,
пороги и бюджет. Добавь короткий фрагмент из AGENTS.md в существующие правила
проекта, проверив путь к скиллу. Не заменяй существующий AGENTS.md целиком.
Вызови `$engineering-decision-policy` или выбери навык в интерфейсе агента.

## Claude Code

Тот же комплект скопируй целиком в
`<project>/.claude/skills/engineering-decision-policy/`. Сохрани проектную
политику в `.engineering-policy/policy.json`; объедини фрагмент CLAUDE.md с
существующим файлом и проверь путь к скиллу. Для явного вызова используй
`/engineering-decision-policy`. Формат навыка общий, отдельной копии алгоритма нет.

## Подключение к своему проекту

Профили сейчас исполняются для `demo/export_rows`. Перед применением к production
замени демонстрационные измерения реальными проверками. Спецификацию адаптера
читай в VALIDATOR.md. Согласуй порядок и минимальные требования с владельцем
проекта; обязательные SLO оставь hard constraints. Сначала подтверди baseline,
потом запускай кандидаты. Сменил policy, scope, suite или инструменты — собери
новую сопоставимую пару отчётов.

Пример задания агенту:

> Примени Engineering Decision Policy к рефакторингу указанного модуля. Сохрани
> контракт API. Используй согласованный Production-профиль и бюджет поиска.
> После каждого кандидата заново проверь hard constraints и все предыдущие
> уровни. Покажи принятый checkpoint, недостигнутые пороги и unknown. Если
> измерителя нет, сначала предложи проверяемые сценарии и адаптер.

## GitHub Pages

В этом репозитории публикуется статический `index.html` из корня ветки main.
Файл `.nojekyll` сохраняет исходную статическую структуру. ZIP находится в dist.
Никакой серверной части и сборки frontend нет. Для обновления страницы после
правки файлов выполни `python3 scripts/build_site.py`, затем
`python3 scripts/package.py`; проверь результат и опубликуй изменения.

## Границы установки

Комплект не устанавливает hooks, не выдаёт доступы, не меняет глобальные правила
и не подключается к API агента. Скилл направляет процесс; принудительное
исполнение требует интеграции валидатора в доверенный CI. Веб-симулятор не
анализирует загруженный код и не запускает тесты в браузере.
