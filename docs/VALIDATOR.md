# Валидатор и адаптеры

## Реализовано в v2

`scripts/evaluate.py` — исполняемый прототип на Python 3.10+ без зависимостей.
Он читает policy и два JSON-отчёта, проверяет типы, соответствие политики,
сопоставимость измерений и правило приёмки. Код не запускает shell-команды,
не редактирует проект и не откатывает изменения. Обратную связь получает агент
или CI; решение о сохранении/отмене патча исполняет внешний оркестратор.

```sh
python3 scripts/evaluate.py \
  --policy configs/production.json \
  --baseline demo/reports/testable.json \
  --candidate demo/reports/compact-regression.json \
  --target source_lines
```

Ожидается `REJECT`: уменьшение числа строк не компенсирует нарушенную
изоляцию вывода. Команда намеренно завершается кодом 20. Получить отчёты заново:
`python3 scripts/run_demo.py`. Сравнение корректного улучшения:

```sh
python3 scripts/evaluate.py \
  --policy configs/production.json \
  --baseline demo/reports/testable.json \
  --candidate demo/reports/efficient.json \
  --target formatter_calls
```

## Контракт policy

JSON — единственный исполняемый формат v2. `schema_version: 2`, profile, scope,
suite_id, search_budget; далее hard_constraints и упорядоченный массив levels.
Оба содержат записи `id`, `label`, `type`, `direction`, `gate`, `unit`,
`evidence_kind`, `method`, `limitation`. Для number есть `min_improvement`.
Binary использует настоящий JSON bool, direction=max, gate=true. Number —
конечное число, без bool, NaN и Infinity. Для min порог задаёт верхнюю границу,
для max — нижнюю. Пороги включительны; выигрыш строго больше min_improvement.
Идентификаторы уникальны во всей политике.

## Контракт отчёта

Пример фрагмента; полный запускаемый отчёт лежит в `demo/reports/`:

```json
{
  "schema_version": 2,
  "policy_sha256": "sha256 канонического JSON политики",
  "scope": "demo/export_rows",
  "suite_id": "export-rows-v2",
  "source_revision": "sha256 исходного файла варианта",
  "environment": "согласованная среда и версия измерителя",
  "experiment_id": "одинаковый ID парного эксперимента",
  "collected_at": "UTC ISO 8601",
  "measurements": {
    "testability": {
      "status": "measured",
      "value": true,
      "evidence": "команда/сценарий, ссылка на лог и ожидаемое поведение"
    },
    "extensibility": {
      "status": "unknown",
      "reason": "сценарий расширения пока не утверждён"
    }
  }
}
```

Хеш policy: UTF-8 JSON, ключи отсортированы, ensure_ascii=false, separators=(',', ':').
Для production нужны хеш дерева/коммита и незакоммиченных изменений, версии
инструментов, lockfile, тестов, workload, окружение и сырые логи. Demo использует
хеш одного модуля, потому что он и есть весь измеряемый исходный scope.
Отчёты пары должны совпадать по policy_sha256, scope, suite_id, environment,
experiment_id; source_revision различается при изменении кода. Измерения каждого
кандидата собираются заново, а не копируются из baseline.

## Статусы

| Статус | Код CLI | Значение |
|---|---:|---|
| ACCEPT | 0 | Текущий критерий улучшен, его gate и защищённый префикс проходят |
| ACCEPT_PROGRESS | 10 | Есть улучшение, текущий gate пока не пройден; остаться на уровне |
| NO_CHANGE | 11 | Значимого улучшения нет; checkpoint не изменяется |
| REJECT | 20 | Hard constraint или защищённый уровень нарушен либо цель ухудшилась |
| INCONCLUSIVE | 21 | Нужное измерение неизвестно; приёмка не подтверждена |
| BASELINE_INVALID | 22 | Исходная допустимость/предыдущий gate не подтверждены |
| INVALID | 23 | Некорректные или несопоставимые входы |

`next_level_allowed` — разрешимость перехода по измерениям префикса, а не команда
перехода: агент ещё должен закрыть бюджет поиска этапа. `all_configured_gates_met`
касается только записанных gates. `global_optimum_proven` всегда false.
Неизвестные нижние уровни не блокируют раннее допустимое улучшение; они видны в
unresolved и должны быть проверены при достижении этапа и на финальном прогоне.

## Как подключить реальные инструменты

Напиши один доверенный адаптер под проект: запускай существующие unit/integration
tests, проверки контрактов, линтер и benchmark; нормализуй результаты в этот
формат. Зафиксируй команды и версии в адаптере/CI. Для расширяемости подготовь
реальный change scenario, для переиспользуемости — нужных клиентов, для читаемости
добавь проверку понимания. Ошибка инструмента — unknown или INVALID, а провал
проверяемого условия — measured со значением, которое не проходит gate.

## Граница доверия и недостающие функции

Отчёт — утверждение сборщика. Хеши и непустая evidence помогают связать записи,
но не удостоверяют их подлинность: сравнитель не открывает каждый лог и не
перезапускает тесты. Для CI собирай отчёты доверенным job из проверяемого дерева;
отдельно контролируй изменения тестов и конфигурации. Подделка измерений,
исключение сложного кода из scope и удаление проверок — ошибки процесса, которые
нельзя устранить одним сравнением JSON.

Прототип не поддерживает произвольные языки «из коробки», подпись артефактов,
проверку свежести по часам, статистические интервалы, автоматический поиск
кандидатов, Git rollback, соблюдение бюджета поиска, CI hooks и доказательство
безопасности. Это расширяемые точки интеграции, не уже готовые возможности.
