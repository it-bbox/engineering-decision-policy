# Engineering Decision Policy · v2

Проверяемая политика инженерных решений для coding agents: обязательные
ограничения, упорядоченные критерии и последовательная оптимизация с проверкой
всех предыдущих уровней на регрессии.

**[Открыть страницу](https://it-bbox.github.io/engineering-decision-policy/)** ·
**[Скачать комплект](https://it-bbox.github.io/engineering-decision-policy/dist/engineering-decision-policy-v2.zip)**

Статус: рабочий прототип сравнителя измерений и демонстрационный адаптер Python.
Эффективность политики на реальных задачах ещё предстоит проверить. Обещания
глобального оптимума, полной безопасности и гарантии всех качеств отсутствуют.

## Быстрый запуск

Требуется Python 3.10+. Сеть, API-ключи и сторонние пакеты для demo не нужны.

```sh
python3 scripts/run_demo.py
python3 -m unittest discover -s tests -v
```

Открой `index.html` в браузере: это автономный русскоязычный лонгрид с
интерактивной моделью, просмотром файлов и скачиванием исходников.
HTML-симулятор иллюстрирует правило на готовых данных. `run_demo.py` действительно
запускает код вариантов, собирает измерения и вызывает валидатор.

## Принцип

```text
Корректный baseline → hard constraints → уровень 1 → уровень 2 → …
Для каждого кандидата: hard constraints + все предыдущие уровни + текущий.
Регрессия → отклонить. Неизвестное → не засчитывать. Порог не пройден → остаться.
```

Production: тестируемость → расширяемость → переиспользуемость → читаемость →
минималистичность → производительность. Это пример предпочтений, не универсальный
стандарт. Обязательная задержка или бюджет памяти остаются hard constraints при
любом порядке. Численные пороги demo иллюстративны и не переносятся в проект автоматически.

Валидатор проверяет предоставленные измерения, а не истинность всей программы.
Он не меняет код, не откатывает Git и не запускает произвольные команды из JSON.
Подробности: [контракт](docs/POLICY.md), [валидатор](docs/VALIDATOR.md).
